# 本番環境デプロイガイド

## 概要

AivisSpeech Engine を本番環境で大規模アクセスに耐えられるように構成する方法を説明します。

## どのデプロイ方法を選ぶべきか

| 規模 | 推奨構成 | 説明 |
|-----|---------|------|
| 個人〜小規模（1台） | Docker Compose | シンプルで運用が簡単 |
| 中規模（2〜5台） | Docker Swarm | 複数ホストでの負荷分散 |
| 大規模（10台以上） | Kubernetes | 自動スケーリング、高可用性 |

### Kubernetes が必要なケース

- 複数サーバーでの自動負荷分散が必要
- ゼロダウンタイムデプロイが必須
- 自動スケーリング（オートスケール）が必要
- 複数サービスの複雑なオーケストレーション

### Kubernetes が不要なケース（Docker Compose で十分）

- 個人サーバー1台での運用
- シンプルな運用を優先
- 学習コスト・運用コストを抑えたい
- サーバーリソースが限られている

---

## アーキテクチャ

### 推奨構成

```
[ロードバランサー/リバースプロキシ]
        ↓
[Gunicorn Master Process]
        ↓
[複数の Uvicorn Worker Processes]
        ↓
[FastAPI Application]
```

# Part 1: Docker Compose を使用したデプロイ（個人〜小規模向け）

個人サーバーや小規模環境では、Docker Compose が最適です。

## compose.yaml の設定

### 開発環境用

```yaml
services:
  aivis-dev:
    build:
      context: .
      dockerfile: Dockerfile
    volumes:
      - ./AivisSpeech-Engine-Dev:/home/appuser/.local/share/AivisSpeech-Engine-Dev
    ports:
      - "10101:10101"
    environment:
      - VV_WORKERS=1
      - VV_ENABLE_TRACING=0
    command: ["uv", "run", "python", "run.py", "--use_gpu", "--host", "0.0.0.0"]
```

### 本番環境用（推奨設定）

```yaml
services:
  aivis-prod:
    build:
      context: .
      dockerfile: Dockerfile
    volumes:
      # 名前付きボリュームを推奨（パフォーマンス向上）
      - aivis-data:/home/appuser/.local/share/AivisSpeech-Engine-Dev
    ports:
      - "10101:10101"
    environment:
      # ===== ワーカー設定 =====
      # ワーカー数: CPU コア数 × 2 + 1 を推奨
      # 例: 4コア → 9, 8コア → 17
      - VV_WORKERS=9
      - VV_BIND=0.0.0.0:10101
      
      # ===== タイムアウト設定 =====
      # ワーカータイムアウト（秒）: 音声合成の最大処理時間
      - VV_TIMEOUT=180
      # Keep-Alive タイムアウト（秒）
      - VV_KEEPALIVE=5
      # グレースフルシャットダウン時間（秒）
      - VV_GRACEFUL_TIMEOUT=30
      
      # ===== リクエスト制限 =====
      # 同時リクエスト数の上限
      - VV_LIMIT_CONCURRENCY=100
      # ワーカーあたりの最大リクエスト数（メモリリーク対策）
      - VV_MAX_REQUESTS=1000
      - VV_MAX_REQUESTS_JITTER=50
      
      # ===== モニタリング =====
      # リクエストトレーシング有効化
      - VV_ENABLE_TRACING=1
      - VV_LOG_LEVEL=info
      
      # ===== アプリケーション設定 =====
      # GPU 使用
      - VV_USE_GPU=1
      # 起動時に全モデルをロードしない（オンデマンド）
      - VV_LOAD_ALL_MODELS=0
      # 変更系 API を無効化（セキュリティ強化）
      - VV_DISABLE_MUTABLE_API=1
      # CORS ポリシー
      - VV_CORS_POLICY_MODE=localapps
    
    # ===== リソース制限 =====
    deploy:
      resources:
        limits:
          cpus: '4'
          memory: 8G
        reservations:
          cpus: '2'
          memory: 4G
    
    # ===== ヘルスチェック =====
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:10101/health"]
      interval: 30s      # チェック間隔
      timeout: 10s       # タイムアウト
      retries: 3         # 失敗許容回数
      start_period: 60s  # 起動猶予時間
    
    # ===== 自動再起動 =====
    restart: unless-stopped
    
    # ===== 起動コマンド =====
    command: ["uv", "run", "gunicorn", "-c", "gunicorn_conf.py", "app_factory:app"]
    
    # ===== プロファイル =====
    profiles: ["production"]

# 名前付きボリューム
volumes:
  aivis-data:
    driver: local
```

### GPU を使用する場合の追加設定

```yaml
services:
  aivis-prod:
    # ... 上記の設定 ...
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: 1  # または "all" で全GPU使用
              capabilities: [gpu]
```

## Docker Compose での起動方法

```bash
# 開発環境
docker compose up aivis-dev

# 本番環境（バックグラウンド実行）
docker compose --profile production up -d aivis-prod

# ログ確認
docker compose logs -f aivis-prod

# 停止
docker compose --profile production down
```

## systemd との連携（サーバー再起動時の自動起動）

`/etc/systemd/system/aivisspeech-docker.service`:

```ini
[Unit]
Description=AivisSpeech Engine (Docker Compose)
Requires=docker.service
After=docker.service

[Service]
Type=oneshot
RemainAfterExit=yes
WorkingDirectory=/opt/aivisspeech-engine
ExecStart=/usr/bin/docker compose --profile production up -d
ExecStop=/usr/bin/docker compose --profile production down
TimeoutStartSec=300

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable aivisspeech-docker
sudo systemctl start aivisspeech-docker
```

# Part 2: Kubernetes を使用したデプロイ（大規模向け）

複数サーバーでの自動スケーリングや高可用性が必要な場合は Kubernetes を使用します。

## Kubernetes マニフェスト

### Deployment

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: aivisspeech-engine
  labels:
    app: aivisspeech-engine
spec:
  replicas: 3  # Pod 数（水平スケーリング）
  selector:
    matchLabels:
      app: aivisspeech-engine
  template:
    metadata:
      labels:
        app: aivisspeech-engine
    spec:
      containers:
        - name: aivisspeech-engine
          image: your-registry/aivisspeech-engine:latest
          ports:
            - containerPort: 10101
          env:
            # ワーカー設定（Pod あたり）
            - name: VV_WORKERS
              value: "5"
            - name: VV_TIMEOUT
              value: "180"
            - name: VV_KEEPALIVE
              value: "5"
            - name: VV_GRACEFUL_TIMEOUT
              value: "30"
            - name: VV_LIMIT_CONCURRENCY
              value: "50"
            - name: VV_ENABLE_TRACING
              value: "1"
            - name: VV_USE_GPU
              value: "1"
            - name: VV_DISABLE_MUTABLE_API
              value: "1"
          
          # リソース制限
          resources:
            requests:
              cpu: "2"
              memory: "4Gi"
              nvidia.com/gpu: 1  # GPU 使用時
            limits:
              cpu: "4"
              memory: "8Gi"
              nvidia.com/gpu: 1
          
          # Liveness Probe（プロセス生存確認）
          livenessProbe:
            httpGet:
              path: /health/live
              port: 10101
            initialDelaySeconds: 60
            periodSeconds: 30
            timeoutSeconds: 10
            failureThreshold: 3
          
          # Readiness Probe（リクエスト受付可能確認）
          readinessProbe:
            httpGet:
              path: /health/ready
              port: 10101
            initialDelaySeconds: 30
            periodSeconds: 10
            timeoutSeconds: 5
            failureThreshold: 3
          
          # Startup Probe（起動完了確認）
          startupProbe:
            httpGet:
              path: /health
              port: 10101
            initialDelaySeconds: 10
            periodSeconds: 10
            timeoutSeconds: 5
            failureThreshold: 30  # 起動に最大5分許容
          
          # ボリュームマウント
          volumeMounts:
            - name: data
              mountPath: /home/appuser/.local/share/AivisSpeech-Engine-Dev
      
      volumes:
        - name: data
          persistentVolumeClaim:
            claimName: aivisspeech-data
```

### Service

```yaml
apiVersion: v1
kind: Service
metadata:
  name: aivisspeech-engine
spec:
  selector:
    app: aivisspeech-engine
  ports:
    - protocol: TCP
      port: 80
      targetPort: 10101
  type: ClusterIP  # 内部のみ（Ingress 経由でアクセス）
```

### Ingress

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: aivisspeech-engine
  annotations:
    nginx.ingress.kubernetes.io/proxy-body-size: "50m"
    nginx.ingress.kubernetes.io/proxy-read-timeout: "180"
    nginx.ingress.kubernetes.io/proxy-send-timeout: "180"
spec:
  rules:
    - host: api.example.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: aivisspeech-engine
                port:
                  number: 80
  tls:
    - hosts:
        - api.example.com
      secretName: aivisspeech-tls
```

### HorizontalPodAutoscaler（自動スケーリング）

```yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: aivisspeech-engine
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: aivisspeech-engine
  minReplicas: 2
  maxReplicas: 10
  metrics:
    - type: Resource
      resource:
        name: cpu
        target:
          type: Utilization
          averageUtilization: 70
    - type: Resource
      resource:
        name: memory
        target:
          type: Utilization
          averageUtilization: 80
```

### PersistentVolumeClaim

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: aivisspeech-data
spec:
  accessModes:
    - ReadWriteMany  # 複数 Pod から同時アクセス
  resources:
    requests:
      storage: 50Gi
  storageClassName: nfs  # 共有ストレージが必要
```

## Kubernetes でのデプロイ

```bash
# マニフェストの適用
kubectl apply -f deployment.yaml
kubectl apply -f service.yaml
kubectl apply -f ingress.yaml
kubectl apply -f hpa.yaml

# 状態確認
kubectl get pods -l app=aivisspeech-engine
kubectl get hpa aivisspeech-engine

# ログ確認
kubectl logs -f deployment/aivisspeech-engine

# スケーリング（手動）
kubectl scale deployment aivisspeech-engine --replicas=5
```

# Part 3: Gunicorn を直接使用したデプロイ（Docker なし）

Docker を使用せず、ホストマシン上で直接実行する場合の設定です。

## 基本的な起動コマンド

```bash
# uv を使用
uv run gunicorn -c gunicorn_conf.py app_factory:app

# または直接実行
gunicorn -c gunicorn_conf.py app_factory:app
```

## カスタム設定での起動

```bash
# 環境変数で設定を上書き
VV_WORKERS=8 \
VV_TIMEOUT=120 \
VV_BIND=0.0.0.0:8000 \
gunicorn -c gunicorn_conf.py app_factory:app
```

## systemd を使用したデプロイ

#### サービスファイルの作成

`/etc/systemd/system/aivisspeech-engine.service`:

```ini
[Unit]
Description=AivisSpeech Engine
After=network.target

[Service]
Type=notify
User=appuser
Group=appuser
WorkingDirectory=/opt/aivisspeech-engine
Environment="PATH=/opt/aivisspeech-engine/.venv/bin:/usr/local/bin:/usr/bin"
Environment="VV_WORKERS=9"
Environment="VV_TIMEOUT=120"
Environment="VV_ENABLE_TRACING=1"
ExecStart=/opt/aivisspeech-engine/.venv/bin/gunicorn -c gunicorn_conf.py app_factory:app
ExecReload=/bin/kill -s HUP $MAINPID
KillMode=mixed
TimeoutStopSec=30
PrivateTmp=true
Restart=on-failure
RestartSec=5s

[Install]
WantedBy=multi-user.target
```

#### サービスの管理

```bash
# サービスの有効化と起動
sudo systemctl enable aivisspeech-engine
sudo systemctl start aivisspeech-engine

# ステータス確認
sudo systemctl status aivisspeech-engine

# ログの確認
sudo journalctl -u aivisspeech-engine -f

# 設定のリロード（ダウンタイムなし）
sudo systemctl reload aivisspeech-engine

# 再起動
sudo systemctl restart aivisspeech-engine
```

# Part 4: 共通設定とパフォーマンスチューニング

## パフォーマンスチューニング

### ワーカー数の最適化

**推奨値**: `(CPU コア数 × 2) + 1`

```bash
# 4コア CPU の場合
VV_WORKERS=9

# 8コア CPU の場合
VV_WORKERS=17
```

**注意**: ワーカー数が多すぎるとメモリ不足やコンテキストスイッチのオーバーヘッドが発生します。

### タイムアウト設定

```bash
# ワーカータイムアウト（秒）
# 音声合成処理が完了するまでの最大時間
VV_TIMEOUT=120

# Keep-Alive タイムアウト（秒）
# クライアント接続の維持時間
VV_KEEPALIVE=5

# グレースフルシャットダウンタイムアウト（秒）
# 既存リクエストの完了を待つ最大時間
VV_GRACEFUL_TIMEOUT=30
```

### リクエスト制限

```bash
# 同時リクエスト数の制限
VV_LIMIT_CONCURRENCY=100

# ワーカーあたりの最大リクエスト数（メモリリーク対策）
VV_MAX_REQUESTS=1000
VV_MAX_REQUESTS_JITTER=50
```

### メモリ管理

Docker でメモリ制限を設定：

```yaml
deploy:
  resources:
    limits:
      memory: 8G
    reservations:
      memory: 4G
```

## モニタリングとヘルスチェック

### ヘルスチェックエンドポイント

- **基本ヘルスチェック**: `GET /health`
- **Readiness チェック**: `GET /health/ready`
- **Liveness チェック**: `GET /health/live`
- **メトリクス**: `GET /metrics`

### ヘルスチェックの設定例

#### Docker Compose

```yaml
healthcheck:
  test: ["CMD", "curl", "-f", "http://localhost:10101/health"]
  interval: 30s
  timeout: 10s
  retries: 3
  start_period: 60s
```

#### Kubernetes

```yaml
livenessProbe:
  httpGet:
    path: /health/live
    port: 10101
  initialDelaySeconds: 60
  periodSeconds: 30
  timeoutSeconds: 10
  failureThreshold: 3

readinessProbe:
  httpGet:
    path: /health/ready
    port: 10101
  initialDelaySeconds: 30
  periodSeconds: 10
  timeoutSeconds: 5
  failureThreshold: 3
```

### リクエストトレーシング

環境変数 `VV_ENABLE_TRACING=1` を設定すると、以下の情報がログに記録されます：

- リクエストID（X-Request-ID ヘッダー）
- 処理時間（X-Process-Time ヘッダー）
- リクエストメソッドとパス
- ステータスコード

## トラブルシューティング

### よくある問題

#### 1. ワーカープロセスが頻繁にタイムアウトする

**原因**: `VV_TIMEOUT` の値が小さすぎる

**解決策**:
```bash
VV_TIMEOUT=180  # より長い時間に設定
```

#### 2. メモリ不足エラー

**原因**: ワーカー数が多すぎる、またはメモリリーク

**解決策**:
```bash
# ワーカー数を減らす
VV_WORKERS=5

# ワーカーの自動再起動を有効化
VV_MAX_REQUESTS=500
```

#### 3. 高負荷時のレスポンス遅延

**原因**: 同時リクエスト数の制限不足

**解決策**:
```bash
# 同時リクエスト数を制限
VV_LIMIT_CONCURRENCY=50

# リバースプロキシでレートリミットを設定
```

### ログの確認

```bash
# Docker Compose の場合
docker compose logs -f aivis-prod

# systemd の場合
sudo journalctl -u aivisspeech-engine -f --since "10 minutes ago"
```

## セキュリティ考慮事項

1. **非特権ユーザーでの実行**: Dockerfile で `appuser` を使用
2. **CORS 設定の適切な構成**: `VV_CORS_POLICY_MODE` と `VV_ALLOW_ORIGIN` を設定
3. **リバースプロキシの使用**: Nginx や Caddy を推奨
4. **レート制限の実装**: リバースプロキシレベルで設定

## リバースプロキシの設定例

### Nginx

```nginx
upstream aivisspeech_backend {
    server localhost:10101;
}

server {
    listen 80;
    server_name api.example.com;

    # リクエストサイズ制限
    client_max_body_size 50M;

    # タイムアウト設定
    proxy_connect_timeout 60s;
    proxy_send_timeout 120s;
    proxy_read_timeout 120s;

    location / {
        proxy_pass http://aivisspeech_backend;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        
        # リクエストIDの伝搬
        proxy_set_header X-Request-ID $request_id;
    }

    # ヘルスチェックエンドポイント
    location /health {
        access_log off;
        proxy_pass http://aivisspeech_backend;
    }
}
```

## まとめ

### 個人〜小規模（Docker Compose）

1. **Docker Compose + Gunicorn** での実行
2. **適切なワーカー数とタイムアウトの設定**
3. **ヘルスチェックと自動再起動の設定**
4. **リバースプロキシの使用**（オプション）

### 大規模（Kubernetes）

1. **Deployment + HPA** での自動スケーリング
2. **Liveness/Readiness Probe** によるヘルスチェック
3. **Ingress + TLS** でのセキュアなアクセス
4. **リソース制限の適切な設定**
